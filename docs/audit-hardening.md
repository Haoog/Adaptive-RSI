# 2026-10 全项目加固

**简体中文** | [English](audit-hardening.en.md)

这批改动集中处理进程、隔离、存储、调度、模型连接、交付和界面的审计问题。[100 项跟踪表](validation/audit-100-implementation-20261027.json) 区分代码实现、验证和剩余限制；测试使用临时项目或协议替代服务，不证明真实模型能力提升。

## 配置和兼容性

- `schedule.working_hours` 支持跨午夜，例如 `[22, 6]`；`[0, 24]` 表示全天，起止相同无效。
- `recovery.provider_retry_minutes` 默认为 `0`，保留人工恢复；设为 `1..1440` 后，暂停连接在等待后允许一次半开尝试。服务的 `Retry-After` 仍优先约束重试。此设置不提供新的调用额度。
- `delivery.deploy.health_attempts` 默认 `1`，可设 `1..10`；`health_interval_seconds` 默认 `10`，范围 `1..300`；`health_warmup_seconds` 默认 `0`，范围 `0..900`。暖机和尝试间隔内只等待，达到阈值后才判定健康失败或进入已授权回退。人工重试重新计数。旧快照缺少这些字段时使用兼容默认值。
- `updates.require_provenance` 默认 `false`，兼容未安装 `gh` 的客户端。设为 `true` 后，安装前额外执行 `gh attestation verify`，要求官方仓库、允许的发布工作流、主线来源及非自托管构建；没有可验证证据时拒绝安装。SHA-256 检查继续执行。该选项不代表所有历史版本都有 attestation。
- 旧额度键 `limits.daily_calls/run_calls/run_seconds/max_changed_files` 和 `evolution.max_calls` 只为历史配置兼容而接受并归零；不限制运行。`limits.command_seconds` 是 `60..86400` 秒的安全超时，原生多轮对话共享这一时限。总 tokens 和费用只记录。

数据库现在使用 `PRAGMA user_version=2` 和带校验和的迁移台账，仍拒绝未来版本；新增表、索引和耗时列是兼容迁移。恢复前检查 SQLite 完整性、外键和运行/任务的项目归属。旧耗时记录继续使用墙上时间差，新记录优先使用单调时钟时长。

设置保存使用版本检查，避免两个窗口静默互相覆盖；`/api/state` 从同一数据库快照读取关联数据。损坏的全局或项目配置可以保留原始审计副本后重置，项目会保持暂停。诊断数据包含只读数据库指标、关系检查、迁移台账和备份清单，不包含凭据或任务正文。

## 保留与容量

运行产物按项目 `limits.retention_days` 清理；发布中的候选、尚在监控的合并运行及完整稳定策略祖先链继续保留。活动运行存在时，不删除退役模型目录。退役凭据按实际清理尝试分批处理，仍被引用的项不会阻塞后续无引用项。

使用 `python3 -m adaptive_rsi --state-dir /绝对路径 archive --max-mb 1024` 导出一致数据库的私有 gzip 快照。所有归档文件合计超过给定容量时拒绝新归档，不覆盖旧归档、不删除在线历史。归档使用跨进程排他锁，文件权限为 `0600`；解压得到 SQLite 文件后，可用现有 `restore` 命令恢复到新目录。归档包含私有项目证据，不应公开上传。

此容量参数约束归档目录，不是整个状态目录的硬上限。运行、任务和调用的原始历史仍可增长；本批保留这些审计及用量记录，不自动删除。需要离线归档管理和磁盘空间监控，不能把压缩快照理解为已完成历史数据自动分层。

## 执行、交付和界面

原生 HTTP 在独立短命进程中执行，可取消真实阻塞请求；打包引擎有专用内部入口。源码读取拒绝链接和特殊文件，检索缓存有总量上限。原生文件工具及命令的写权限按宿主封存的计划范围约束，元数据仍受保护。Docker 命令只挂载已经存在的可写范围，缺失文件需先通过文件工具创建；对单文件挂载的原子替换可能被 Docker 拒绝。

普通模型/检查共享进程级执行容量；性能对照独占该容量并串行运行，减少受管任务互相干扰。外部系统负载仍可能影响测量。新增回归可以包含最多 8 个文件，隔离测试保留受支持的安全 pytest 参数；Go JSON 输出可提供结构化执行摘要。

授权、发送意图和回执分别持久化。慢速 GitHub 操作移出全局调度锁，发送前短锁复核授权/所有者；在已经记录发送意图后撤销授权，不能保证远端动作被撤回。不确定网络结果继续对账，不盲目重复请求。合并保护读取只是提示，GitHub 仍执行实际规则。

活动历史支持游标分页；历史时间包含年份和时区。禁止浏览器存储时仍可操作页面，草稿无法持久化时显示提示。确认框管理焦点，模型部分保存显示剩余状态。桌面备份通过 Rust 流式下载到私有临时文件，支持进度和取消。服务工作线程只缓存无查询参数的公开图标，可执行资源和页面始终走网络；不提供离线控制台。

## 第三期深度缺陷与跨平台加固

- **索引与分批清理**：补齐 `events(kind, created)`、`phase_times(run)`、`remote_waits(run)` 和 `task_revisions(task)` 关键覆盖索引；`phase_times`、`remote_waits`、`task_revisions`、`submissions` 的级联清理引入分批限流（LIMIT 500），避免大批量删除锁住 WAL；`events` 历史清理改用单次索引偏移查找替代无索引子查询全表扫描。
- **沙箱隔离与环境适应**：`scrub_tree` 允许指向外部环境的良性软链接（如包管理器硬链接或系统工具链），严格阻止指向控制器状态和凭据目录的跨目录软链接；当工作区只读时沙箱临时目录回退至系统临时目录；测试评估器兼容 Unicode 勾选标记与 Vitest 耗时格式，冻结基线跳过损坏软链接。
- **模型连接与上下文修剪**：原生模型对话在逼近上下文上限时自动修剪过长工具输出并保留摘要；Gemini 协议保留 tool_call_id；Claude 2 / Opus 的 max_tokens 严格限制在 4096 范围内；并发 finish 与工具调用自动转换为引导消息。
- **发布与桌面跨架构**：GitHub Release 工作流解析增强对行尾注释和引号值的兼容；桌面更新安装包动态适配 `x86_64` 与 `arm64` 架构，下载路径缺少 `HOME` 时自动降级至系统临时目录；PR 交付按钮增加防重入锁定；CSP 补全 `object-src 'none'`。


## 明确保留的限制

- macOS Seatbelt 下的普通进程组清理不能保证终止主动 `setsid()` 脱离且快速重新挂接的后代。Docker 检查使用容器清理。不能把本批进程修复宣传为 macOS 完整进程树监管。
- 开始执行、验收后和发布前的远端基线仍重新获取，防止以缓存 SHA 交付陈旧候选；没有为节省请求而缓存这些关键检查。
- 桌面已准备 Developer ID 签名、hardened runtime 和公证配置通路；真正签名、公证及 Gatekeeper 验证需要 Apple 凭据和一次正式构建。未提供凭据时仍为 ad-hoc 构建，不能标记为已公证。参见 [Tauri 签名文档](https://v2.tauri.app/distribute/sign/macos/)。
- 随机状态转换、短时资源压力、双语无障碍和自动翻译检查只覆盖各自定义的边界，不能代替长期生产观测、完整无障碍审计或真实模型评测。
