# 离线调度与成本评估

**简体中文** | [English](policy-evaluation.en.md)

从仓库根目录运行。两种模式输出 JSON，可用 `--output` 写到一个新的文件。它们只读取显式指定的本地输入，不启动应用、联系模型或更新调度。

## 回放合法任务队列

```sh
python3 -B scripts/benchmark_history.py \
  --policy-replay tests/fixtures/policy_queue_trace.json \
  --workers 1 --planning-slots 1 --old-after 30 --old-quota 1 \
  --urgent-quota 1 --quota-window 100
```

同一输入分别运行基线、隔离规划、老任务机会、跨项目用户加急四种情景。后三种各自与基线比较。回放复用应用的任务排序和项目公平排序，按项目权重计入近 24 小时工作槽占用，模拟同仓库写入互斥。规划槽独立计数，仅在同仓库已有写任务时预先计算。普通写任务领取时检查从预规划开始到领取期间的主线更新，过期方案回到串行规划并按任务记入返工秒数。回放没有执行实际规划或 Git 写入。

输入格式 1 见[固定队列样例](../tests/fixtures/policy_queue_trace.json)。实际回放使用自行准备的脱敏 `redacted_history` 文件。任务应提供 `id`、`project`、`source`、`created`、`ready_at`、`plan_seconds` 和 `work_seconds`。时间使用 Unix 秒，时长使用秒。`projects` 将项目映射到脱敏仓库标识和可选权重，同一仓库的项目使用同一个仓库标识。`mainline_changes` 必须覆盖每个纳入的仓库，空数组表示观察期间确实没有主线更新。每个任务从 `ready_at` 连续满足准入条件，或通过 `eligible_windows` 指定半开时间窗，最后一个窗以 `null` 结束，供回放排空。暂停、工作时段、前置任务、退避等导致的不合格时段应从窗口中排除。已出队后重试的领取可用独立脱敏标识表示。输入缺少完整准入或主线证据时，只能评估另行声明的样例场景。

`claimable_wait_seconds` 只计符合条件且尚未领取的时段，含等待工作槽或公平分配的时间。老任务按这个累计时长达到 `--old-after` 后，可在同项目内获得每个滚动窗口最多 `--old-quota` 次插队机会。`urgency` 保留现有排序语义。只在有明确证据时将 `urgency_origin` 标为 `user` 或 `system`，无法确认时使用 `unknown` 或省略。用户队首任务可参与跨项目竞争，每个滚动窗口全局最多 `--urgent-quota` 次跨项目提拔。单项配额设为 `0` 可关闭该实验。报告给出逐任务等待差值、普通任务等待的总量/中位数/最大值，以及各项目等待、提拔与按权重归一的工作槽占用。

回放从空队列和公平账本开始。工作时长、主线更新和准入窗口作为固定输入，未模拟 Issue 同步可以与部分生产任务并行的例外、实时资源压力或改变领取顺序后对依赖和主线事件的反作用。样例及真实脱敏回放都只支持对所给输入的描述和情景比较。

## 生成阶段历史与自动任务费用区间

```sh
python3 -B scripts/benchmark_history.py \
  --policy-history /path/to/offline-snapshot.sqlite3 \
  --start 1700000000 --end 1702592000 --project REDACTED_PROJECT_ID
```

使用从现有应用数据库安全备份并完成脱敏的独立 SQLite 快照。输入目录不应有 `-wal`、`-shm` 或 `-journal` 伴随文件，也不要使用正在写入的数据库或从其中直接拷贝的主文件。读取方式不会补做 schema 迁移，快照需要具备用量报告当前使用的字段。`--project` 可省略，时间窗为 `[start, end)`。

- `stage_history` 按项目、任务来源、角色、供应商、模型、推理强度、调用单位以及调用时保存的费率分组，每组一条样本代表一次运行中的同组调用。报告列出运行样本、不同任务数、有效价格样本及质量覆盖。检查与评审同时通过才算通过，任一明确失败计为失败，资料不足单列。质量结果属于整次运行，可能出现在多个角色或模型组。费用和质量分别要求至少 8 个有对应证据的不同任务。比较结果仅为历史观察，任务复杂度、重试和模型选择均可影响分组。
- `automatic_task_cost` 对终态 `system_` 任务统计窗口内所有尝试及实际调用，包括可定价的失败调用。任务按项目、来源及记录的完整调用路由和费率组合分组。只有样本中的各次尝试都在窗口内，任务也在窗口内创建并达到快照中的终态，才纳入区间。至少 8 个可完整定价的任务才输出 USD 的 P25、中位数和 P75。窗口外或未完成任务、缺调用、未知用量与未知价格都单独计数，无法估价时返回 `null`。明确记录的零费率可产生真实的零估算。

区间描述已观测样本的中间一半，不充当账单或下一个任务的费用保证。缺样时应读 `insufficient_samples` 和覆盖数。报告不会触发自动延迟。

仓库中 [历史规模基准](validation/history-performance-20261028.json) 使用合成任务，[桌面用量评审](validation/desktop-task-usage-review-20261023.json) 记录验证结果。这两份材料均缺少实际准入时间窗、完整主线事件与可定价逐任务样本，无法用于测算真实生产收益或成本区间。
