## 行为变化

- 原生工具超过 16 KiB 的文本保存到运行自有产物，返回摘要、字节数、SHA-256 和不透明 ID；`read_artifact` 分页，`search_artifact` 按字面量搜索。产物位于工作区之外，按运行、调用和角色校验归属，拒绝路径穿越、符号链接、硬链接、损坏和过期内容。单产物 16 MiB、总量 64 MiB、128 个的边界会明确报错，不增加模型判断调用。过期产物不自动清除，仍由运行保留清理管理；预算统计覆盖该运行产物目录。
- 具体型号能力区分官方规则、保守推断和人工覆盖。官方规则携带来源及本地核对日期，日期不是供应商变更时间。旧型号缺少当前逐型号证据时保留推断标签。目录、角色快照、诊断和实际原生请求使用同一覆盖值及预算策略；损坏覆盖回退，目录显示错误标记；超大目录不会静默丢失已保存覆盖。
- `dispatch_unknown` / `rerun_unknown` 可只读重新查询 GitHub 候选。操作员必须明确选择服务端返回的运行，后端复核仓库、工作流、ref、SHA、operation ID、现有 run ID 与新 attempt；不重新 dispatch 或 rerun。审计保存原始与展示候选、原状态、选择及来源标签；标签不等同于认证人员身份。
- CLI 使用独立 HOME 内的 0700 临时目录，拒绝已有链接；macOS 只增加 `/dev/null` 的精确写权限以支持子进程空标准流，不扩大项目外数据写入范围。
- 测试 worker 写入阶段、选择器、线程栈及有界子进程诊断，保留重入拒绝、父进程监视和进程组回收。历史挂起已定位在组内测试打印 OK 之后、下一组开始之前；截断的 faulthandler 输出支持取消计时器窗口这一假设，但 300 次有界探测未复现，具体根因未知。诊断改为进程级定时，不宣称消除全部挂起。

## 真实更新

独立复制官方 0.5.130 应用，隔离 HOME 和控制器状态，通过真实应用界面使用官方签名包更新到 0.5.131。

1. 正常更新：替换、重启、`succeeded` 回执、签名验证与健康 HTTP 200 均通过。
2. 下载中断：观察真实分段后结束该副本，保留 37,054 字节和下载身份；重启后得到 15,773,688 字节的完整签名缓存，再应用内安装成功。未采集 HTTP Range 传输字节，不宣称节省量。
3. 缓存篡改探测：磁盘缓存的一字节修改未进入最终安装，安装回执仍是官方原始摘要并健康启动；未观察到失败转换，不能算作签名失败恢复验收。
4. 安装失败：将隔离安装临时路径替换为普通文件，真实安装返回 `failed / update_install_failed`，旧 0.5.130 应用保留、旧引擎重新启动且健康 HTTP 200。保留失败回执后修复临时路径，再次应用内安装成功，0.5.131 回执为 `succeeded`，健康 HTTP 200。

尚未在真实环境覆盖替换后新版本启动失败、断电、磁盘损坏和完整故障矩阵；这些边界仍为 partial。Rust 固定回归对签名失败、回执状态、启动健康和恢复提供受控验证，不能替代真实故障演练。
