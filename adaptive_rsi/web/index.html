01

任务来源与时间

不需要先设定目标。启用后，巡检和 Issues 都能主动提供任务。

所有来源先评估收益、证据、成本、风险和不做的影响。暂缓任务仅在基线或证据变化后重新评估；不采纳的任务需手动重新考虑。

02

模型与推理强度

每个角色单独调用。默认不替换不可用的模型；可在高级配置中显式指定备用路由。

第三方模型服务

支持官方 API、中转服务与本地模型。按协议接入 Responses、Chat Completions、Anthropic Messages、Gemini 和 Ollama。填写接口根地址及密钥环境变量名；实际调用会验证工具调用和结果格式。原生 Anthropic、Gemini、Ollama 请选服务默认推理强度。

独立检查正确性、安全、可维护性、架构、测试与范围。达到阻断级别的问题或任一维度未通过，均不能交付；证据不足同样不放行。

03

资源与交付

所有改动保留为本地候选。只有在任务详情逐次确认后，才推送分支并创建 PR；不自动合并。

Codex 按会话计数；原生接口按 HTTP 请求计数，工具往返也消耗调用预算。原有每轮 5 次可能不足，请主动调整；不会自动扩额。

04

自我改进与验证

普通任务与策略实验分别计数。证据不足时继续使用稳定版；新策略先监测，失败自动恢复。

05

软件版本更新

全局设置。只安装正式发布包；不修改你的源码仓库。运行中等待空闲，启动检查失败恢复旧版和数据库。

自动更新仅限相同主次版本的补丁；其他版本需确认。插件已加载的技能和元数据仍需刷新市场并重启 Codex。更新源为 Haoog/Adaptive-RSI 的 GitHub Releases。

高级配置覆盖 / JSON

仅填写要覆盖的字段。可配置备用模型、Issue 排除标签、容器资源和保留期限。

运行中的任务保留开始时的完整配置。

当前项目的语言能力

识别语言不等于检查可运行。只有实际沙箱检查成功，才会记录为通过。SQL、Shell、PowerShell、HTML/CSS、Docker 与 CI 配置参与分析。

接入项目

选择已有提交的 Git 仓库根目录。运行器在独立快照中工作。

每行一个 GitHub 仓库链接，分别克隆、分别管理。私有仓库使用本机 gh 登录权限；导入后保持暂停。

不同项目的任务、记忆、配置和预算分别管理；通过验收后仍需确认才能创建 PR。
